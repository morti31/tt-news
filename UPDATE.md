# How each update run works

The site is static. All content lives in `data/news.json`; `index.html`, `styles.css` and `app.js` only change when the design changes. Each scheduled run follows these steps.

1. Pull the latest `main`.
2. Start with the news scan digest. `.github/workflows/news-scan.yml` runs hourly on GitHub and saves recent headlines (Google News searches in English, Chinese, Japanese, Korean, German, French, Spanish and Portuguese, the sites' own feeds, and official WTT results and schedules for events on now) to the `scan` branch. Read it with `git fetch -q origin scan && git show origin/scan:digest.md` (the full data is `digest.json` and `wtt.json`). The end of the file lists which sources worked. Many digest links are Google News redirects that the sandbox can't open: the scan resolves them to the real address (`real: <url>` on the line) and saves a short text excerpt of the newest pages to `pages.json` (`git show origin/scan:pages.json`, keyed by the digest URL; lines with `text in pages.json` have one). Use the excerpt to read a lead, then confirm it against the original source (open the `real:` address with WebFetch where it is allowed) or a second source; excerpts are truncated and never a substitute for checking. Check every headline against its original source before using it: the digest is a lead list, not a source. Then search for table tennis news published since `updated` in `data/news.json`, in English and in the original languages, to fill the gaps. Search in each language with native terms (for example 乒乓球, 国乒, 乒超 in Chinese; 卓球, Tリーグ in Japanese; 탁구 in Korean; Tischtennis in German; tennis de table in French). Check, as a minimum:
   - International: worldtabletennis.com, ittf.com, ettu.org, butterflyonline.com
   - China: Xinhua and China Daily sports, CCTV Sports, NetEase (163.com) and Sina sports, the Chinese Table Tennis Association, China Super League coverage
   - Japan: jtta.or.jp, tleague.jp, TV Tokyo table tennis, Spread Sports
   - Korea: KTTA, Star News Korea, Yonhap
   - Germany: tischtennis.de, ttbl.de, mytischtennis.de
   - France: fftt.com
   - India: Ultimate Table Tennis, TTFI
   - England and UK: tabletennisengland.co.uk, Table Tennis Scotland and Wales
   - news for any event in `events` that is on now

   Write all stories in English. For a story based mainly on a non-English source, add `"lang"` with the language name (for example `"lang": "Chinese"`) and add the language in brackets to the source name, such as `"NetEase (Chinese)"`. Translate names using standard English spellings (Wang Chuqin, not 王楚钦). When English and non-English sources disagree, prefer the most recent report from the source closest to the player or federation, and say who reported it (only then: agreed results and facts need no attribution).
3. Add new stories. For each one:
   - `category` is one of International, England, Clubs, Equipment.
   - Write the headline and a summary of one to three sentences in your own words. No copied sentences, and any quote under 15 words.
   - Link every source used. Leave out anything sources contradict rather than guessing.
   - For a story about a single match result, add `"score"` (for example `"3-2"`), which appears on the story's artwork.
   - Give the story an `image` where a suitable one exists, in this order of preference:
     0. If the story has official video (`videos`), the first video becomes the lead image automatically, so no `image` is needed.
     1. A photo of the main player from Wikimedia Commons, only where the file page names that player and the licence is CC0, public domain, CC BY or CC BY-SA. Use crowd or group shots only if the player is clearly the subject. Format: `{"type":"photo","url":"<1280px upload.wikimedia.org thumbnail>","alt":"...","caption":"<who, where, year>","credit":"<author as on the file page>","licence":"CC BY 4.0","licence_url":"...","page":"<Commons file page>"}`.
        Never use a photo that shows another event's branding (for example Olympic, Pan American Games or World Championships livery on a story about a different tournament). Only use an event-branded photo when it is from the same event as the story. When in doubt, use an illustration instead.
     2. A generic table tennis photo from Unsplash or Pexels for stories without a single named player (equipment, clubs, rule changes), in the same format with the photographer as credit and "Unsplash Licence" or "Pexels Licence".
     3. An illustration for stories tied to a place or an object: reuse one in `img/cartoons/` if it fits, or add a new one to `tools/draw_illustrations.py` and run it. Match the existing style exactly: black fine-line drawing with hatching, `currentColor` strokes, no colour, no text except plain labels, no jokes or speech bubbles, and never a real person's likeness. Format: `{"type":"cartoon","src":"img/cartoons/<name>.svg"}`.
     4. Otherwise leave `image` out and the site draws its own table illustration.
     Never use photos from news sites, WTT, ITTF or federations, and never use a photo whose licence you could not check.
   - Results: whenever a story or article reports match results, add `"matches"` (format documented at the top of `tools/components.py`). The first entry is the headline result and appears as the scoreboard at the top of the page; add the other results from the same story after it (semi-finals, other finals, team ties). Include `"games"` point scores only when a source gives them, checked against at least one source, in the same side order as `"sides"`. For team ties, add each rubber under `"rubbers"`. Never guess a score.
   - Headlines name the competition in full: "WTT Champions Montpellier", "WTT Star Contender Muscat", "Singapore Smash", "WTT Finals Hong Kong", "Asian Championships", "China Super League", never just the host city or venue ("Montpellier draw" is wrong; "WTT Champions Montpellier draw" is right). The same applies to `title`, `headline`, `standfirst` and scoreboard `event` labels.
   - Equal prominence: never give one gender's results more prominence than the other's. If a story covers both men's and women's events, its `matches` must include at least one men's and one women's result (labels starting "Men's" and "Women's"); the site shows them side by side at the same size. Don't put a single-gender score badge (`score`) on a story that covers both. The same goes for headlines, standfirsts and lead paragraphs: where a story covers both, lead with both, not just the men's result.
   - Draws: when an event's draw is published, create `data/draws/<WTT event id>.json` and set `"draw": "<id>"` on the draw story and article. Try `python3 tools/fetch_draw.py <id> "<event name>" <host city UTC offset>` first. If WTT can't be reached, keep the file current by hand from published results: after each round, fill in `winner` (0 or 1), `score` (e.g. "3-1") and the next round's players, and set `updated`. Use the same names as the rest of the site.
   - Videos: add `"videos"` (YouTube `id`, a short `title` in the form "Player A vs Player B, round", and `channel`) when official highlights or full matches exist. Only use channels run by WTT, the ITTF, continental or national federations, league organisers, or their broadcast partners (TT11TV describes itself as a WTT and ETTU partner). Before adding a video, check its title and uploader with `https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<id>&format=json`; skip it if you can't confirm it's the right match and an approved channel. Highlights often appear a day or two later, so on every run, check stories and articles from the last seven days that have results but no videos.
   - WTT data: give every WTT event page a `wtt_id` (the number in its worldtabletennis.com `eventInfo?eventId=` link) and `utc_offset` (the host city's offset in hours) as soon as the event appears on WTT. With those set, the WTT sync (`.github/workflows/wtt-sync.yml`, every 30 minutes) fills in match fixtures from WTT's order of play, refreshes the draw and the rankings, and the event page and scores strip show live scores from `/api/live`. Don't hand-enter match fixtures for an event with a `wtt_id`; session times still go in by hand.
   - Live streams: the site finds WTT's YouTube broadcast for an event on its own (`/api/stream`, matching the event's city and year in WTT's stream titles), shows it on the homepage, the event page and the scores strip while it's live, and offers the latest session to watch back once it ends. If WTT names an event's streams differently, set `stream_q` on the event page in `data/events.json` to words that appear in the stream titles.
   - Top stories (homepage and story pages) are chosen by `top_stories()` in `tools/build_site.py`: event prestige, freshness (halving every 18 hours), full article, results, official video and whether the event is on now, with no more than a fair share from one event. Latest is strictly newest first. You don't set either by hand; the lead story is still the one marked `"top": true`.
   - Lead image order, everywhere on the site: official video first (the first entry in `videos`), then the event poster (stories with `event`), then a licensed photo, then an illustration. The site applies this automatically; never set a cartoon or photo on an event story to override a video or poster.
   - Homepage highlights: the homepage now pulls WTT's newest match highlights automatically (`/api/highlights` in worker.js reads the WTT YouTube channel's Videos tab, matched on the event's `stream_q`), so you don't need to add WTT clips by hand. Keep `highlights` in `data/news.json` only as the fallback for events WTT doesn't cover (continental championships, leagues): official clips (same channel rules and oEmbed check as `videos`) as `{"id", "title", "channel", "event": "<hub id>", "date", "gender": "M" or "W"}`, newest first, dropping clips more than 30 days old, with women's clips as well as men's.
   - Social posts: add `"social"` (`platform` "instagram" or "x", the post `url`, and `account`) for posts from official accounts only: WTT (@wtt), the ITTF (@ittfworld), continental and national federations, leagues, clubs and the players' own verified accounts. Pick posts about the story's event with match photos or video, check the caption matches, and keep it to one or two per story. Where a story covers men's and women's events, don't feature only one side.
   - Adding or correcting `matches`, `draw`, `videos`, `social` or `image` on an already-published article is a data update, not new writing: commit it straight to `main`, set the article's `modified` time, and leave the article text alone. Changes to the article's wording still go through a review pull request.
   - Lead story (`"top": true`, exactly one story): choose it on every run with these rules, in order.
     1. While an event with prestige 3 or more in `data/schedule.json` is on, the lead comes from that event: the draw before play starts, then the day's main results, then the finals.
     2. Otherwise, the newest significant story leads, ranked first by the event's prestige tier, then by how recent it is.
     3. No story stays as the lead for more than about 24 hours if anything comparable has happened since.
     4. When the best men's and women's stories are of similar weight, alternate between them so neither side holds the lead slot run after run. Check which side the previous lead covered.
   - Event hubs: major tournaments have a hub page built from `data/events.json` (`/events/<id>.html`) with Eleven's poster, results, draw, schedule, videos and news. Set `"event": "<hub id>"` on every story and article about a hub event; its results, videos and links then appear on the hub automatically, and the poster becomes the lead image unless there is official video or a suitable photo. Add a hub for each WTT Champions, WTT Star Contender, WTT Finals, Grand Smash, World Cup, World Championships, Olympic and continental championship event at least two weeks before it starts (`id`, `schedule_id` matching `data/schedule.json`, `name` as used in headlines, `group` "WTT Series", "Majors" or "Continental", `tier` from the poster tiers in `tools/posters.py`, `series`, `city`, `country`, `year`, `start`, `end`, optional `venue` only if confirmed, `events`, `coords`, `draw` once published, `live: true` for WTT events). For continental championships also set `region` ("Asia", "Americas", "Europe", "Africa" or "Oceania"), which gives each continent its own poster colour. Always append new hubs to the end of `events`: `tools/posters.py` picks each poster's photo, accent colours and layout so that no two posters look alike, working through the file in order, so appending keeps existing posters unchanged. Then run `python3 tools/posters.py <hub id>` to render `img/posters/<hub id>.jpg` (wide) and `img/posters/<hub id>-sq.jpg` (square, used on phones and in small slots) and commit both. New photos go in `img/posters/photos/` and must be added to `PHOTOS` in `tools/posters.py` with the photographer and page (Unsplash Licence or CC0 only, no event branding visible). Illustrations stay for stories not tied to an event (equipment, features, rule changes).
   Every story in `data/news.json` is either the homepage card for a full article (see Length below) or a quick update: a headline and a one-sentence `summary`. Give every new story a `published` time (current UTC time, ISO format, to the minute, spaced a few minutes apart when adding several).
   - **Quick updates** (`"kind": "Update"`) are for news that is real but short: a confirmed withdrawal, a late schedule change, a single result, a federation announcement, a squad selection, a league result with only a few verified facts. Don't hold back a verified story because it can't reach 400 words, and don't pad it. Use a quick update whenever the verified material supports only a few paragraphs. As a guide, keep full articles (400 words or more) as a healthy share of what a run publishes, around half or more over a week; the rest can be quick updates. There is no daily cap, but never use a quick update for something that will be covered by that day's preview or review, and fold several small items from one event into one quick update or the review rather than posting each separately. Give it a `summary` and a `body` of one to four short paragraphs, with `sources`. It gets its own page labelled "Quick update", which is kept out of Google (`noindex`) and the sitemaps automatically. When more material arrives, turn it into a full article (same story `id`, add the article file) rather than adding a second story.

   Full articles:
   - **Length (Google News)**: a full article is at least 400 words, so that each page is substantial enough for Google News and search. Short news is a quick update instead (below), so write a full article whenever the verified material supports one. Aim for 450 to 800 words for news and match reports, 600 to 900 for day previews and 700 to 1,000 for day reviews. Build length from verified material, never padding: full results with game scores, rankings, seeds and ages (from `data/rankings.json` and WTT's `GetEventSchedule`, which has birth dates), match durations and timeouts (WTT's `GetOfficialResult` match cards), what's next and when (UK time), how to watch, earlier results and quotes from published interviews. Use `## ` subheadings to organise anything over 500 words, `**bold**` for a match line ("**Wang Manyu v Hana Goda (12.10pm UK)**"), and a list (a body item whose lines start with "- ") for results in full and orders of play. If a story can't reach 400 words with verified material, fold it into a related article (the day's review, a preview, or a weekly round-up for its section), or publish it as a quick update (above). Pages under 400 words are automatically kept out of Google (`noindex`) and out of the sitemaps.
   - Full article format: `data/articles/<slug>.json` with `slug` (kebab-case, unique, keyword-led: "wtt-champions-montpellier-2026-day-two-preview-order-of-play"), `story_id` (the matching story's `id` in `data/news.json`), `category`, `date`, `published` (the current UTC time in ISO format, to the minute; if you add several articles in one run, space their times a few minutes apart), `title` (under 110 characters), `seo_title` (under 60), `description` (140 to 155 characters), `standfirst` (one or two sentences), optional `lang`, `image`, `matches`, `videos`, `event`, `draw`, `kind` and `day`, `body` (a list of paragraphs, subheadings and lists), and `sources`. The story in `news.json` carries the headline and a one-sentence summary for the homepage card, with no `body`.
   - Video first: every match report, preview and review about an event WTT films gets official highlights in `videos` (from Eleven's feed, see "Highlights" below). The first video becomes the lead image on the homepage and the article page, ahead of the event poster, photos and illustrations, so add the most important match first.
   - Byline: no `"author"` field and no personal names anywhere on the site. Every story, article, feature and guide is credited to the Eleven Team by the build, and the About, Contact and article pages name no individual. Never write the names of Tom, Michael or Michelle in published copy.
   - Style: follow STYLE.md (Guardian-style news writing) for every summary, body and article. In short: the intro is the news in one sentence; state results, scores and confirmed facts without attributing them to an outlet; attribute only quotes, opinions, unconfirmed claims and conflicting reports; one idea per paragraph; end on what happens next. Keep allegations, reported claims and confirmed fact clearly separate. Quote only words that appear exactly in a source. Quotes from players and coaches (press conferences, mixed zones, interviews, their own social posts, and your own translations of them) can run to two or three sentences, up to about 40 words; a reporter's or outlet's own sentences are paraphrased, never quoted. See STYLE.md on quotes. No AI disclosure line, no clichés, no em dashes.
   - Check every name, score, date and ranking against the sources before writing. If sources conflict, say so in the article or leave the detail out.
   - Publishing: all news articles, day previews, day reviews and quick updates go straight to `main`, with no review pull request. Features (FEATURES.md) and guides (GUIDES.md) also publish straight away, from their own scheduled runs. Because nothing is checked before it goes live, verify every fact, name, score and quote against its source before committing, and fix any mistake you find in an earlier article in the same run, adding `modified`.
   - Don't commit anything in `news/`, `sitemap.xml`, `robots.txt`, `feed.xml` or `data/article-index.json`: Cloudflare builds those from the article files with `python3 tools/build_site.py` on every deploy.
4. Never remove old stories. Eleven is a news site and its archive matters: quick updates exist only in `data/news.json`, so deleting one deletes its page. Leave every story in place (the homepage and the Latest list already show only the newest).
5. Update `results` with finished matches from events on now or just ended (finals and semi-finals for WTT events, title-deciders for club competitions). Keep the three most recent events.
6. Update `rankings` only from the official ITTF world ranking, published by WTT at https://www.worldtabletennis.com/rankings (its data file is https://wtt-web-frontdoor-withoutcache-cqakg0andqf5hchn.a01.azurefd.net/ranking/SEN_SINGLES.json: use `SubEventCode` "MS" and "WS", `CurrentRank`, `RankingPointsYTD` and `PreviousRank`). Never take rankings or points from Butterfly, Tabletennis Reference or other third parties. When a new ranking week is out, save the data file and run `python3 tools/rankings.py <saved file>`: it writes the top 100 to `data/rankings.json` (the Rankings page) and the top 10 in `data/news.json` (the sidebar), with names in the site's spellings. Commit both. If the official list can't be reached, leave the rankings as they are.
7. Keep the schedule in `data/schedule.json` current (`data/news.json` no longer holds events):
   - Add newly confirmed tournaments and club competitions from the ITTF/WTT, ETTU, TTBL, T.League, CTTSL and UTT calendars, and move anything in `tbc` into `events` once dates are published. Leave past events in place; the site hides them.
   - Add `fixtures` with real times (UTC, ISO format, with `event_id`, `name`, `start`, `end`, `source`) for any event within the next 14 days: session times as soon as the organiser publishes them, then notable matches once the draw is out, for example `"WTT Champions Frankfurt: Lebrun v Moregard, quarter-final"`. Use times from the organiser, live-score sites (WTT, Flashscore, SofaScore) or the federation, and convert local times to UTC. Keep each fixture's `id` stable when updating its time, so subscribers' calendars update rather than duplicate.
   - Remove fixtures more than 7 days old.
   - Run `python3 tools/build_site.py`, which checks the schedule (fix anything it prints as a "schedule warning") and rebuilds `calendar.ics`. Commit `data/schedule.json` and `calendar.ics`. Cloudflare also rebuilds the calendar on every deploy, so it always matches the schedule.
   - Check every live or upcoming event in the next 14 days on each run, not just new ones: if a date, venue, session time or match time has moved, update the existing entry in place (same `id`) rather than adding a new one.
8. Set `updated` in both JSON files to the current UTC time, check the JSON parses, then commit with a message like `Update 2026-10-27 09:00` and push.

## Catching up after missed runs

Runs sometimes don't happen (usage limits, outages). Every run starts by checking for gaps, so the site never looks as if it stopped:

- Compare the "updated" time in `data/news.json` with now. If it is more than one scheduled interval old, this is a catch-up run: search the whole gap, not just the last few hours.
- At a big tournament (3 stars or more), check that every playing day since the last run has both its preview and its review. Publish any that are missing, oldest first, with the real `published` time (never back-date) and `date` set to the day they cover. A preview for a day already played keeps its preview form and order of play; publish it just before that day's review so the daily run reads in order. A finished event's finals review comes last and leads as the `top` story.
- Publish the gap's other news as usual (full articles where the material supports one, quick updates otherwise), and apply its knock-on changes.
- Only set "updated" in `data/news.json` to now once the whole gap is covered, so a run that stops halfway leaves the rest for the next one.

## Schedule

Every 4 hours as standard. Hourly while an event with prestige 3.5 or above is on (Mixed Team World Cup, WTT Finals, China Super League Finals, Grand Smashes, World Championships, Olympics).

## Daily previews and reviews at big tournaments

For every tournament rated 3 stars or more (`prestige` 3 or higher in `data/schedule.json`) that runs over three days or more, Eleven publishes a full preview before each day's play and a full review after it. That covers WTT Champions events, Grand Smashes, the WTT Finals, World Cups, World Championships, the Olympics, continental championships rated 3 stars or more and the China Super League finals. It doesn't cover regular league weekends (T.League, Bundesliga) or single European Champions League ties. Both are full articles (with a matching story in `news.json`) and go straight to `main`, like all news. Model them on the match-day previews and reports of BBC Sport, Sky Sports, UEFA and the WTA, written in STYLE.md style. The Montpellier day two preview and day one review (`data/articles/wtt-champions-montpellier-2026-day-*.json`) are the templates.

- **Data**: get the day's order of play, seeds and birth dates from WTT's `GetEventSchedule/<wtt_id>`, and results, game scores, durations and timeouts from `GetOfficialResult?EventId=<wtt_id>&include_match_card=true&take=100`, both through the probe workflow. Rankings come from `data/rankings.json`. Times in the schedule are local to the venue: convert them to UK time.
- **Preview** (600 to 900 words): post it in the first run of a playing day that falls before the first session starts; if no run falls before play, post it in the last run of the evening before. Story `id` `<hub id>-day<N>-preview`; article slug `<hub id>-day-<N in words>-preview-order-of-play`; `"kind": "Preview"`, `"day": N`, `"event": "<hub id>"`, category International, no `top`. Sections: two intro paragraphs (what the day decides, the standout matches, session times in UK time); `## The big matches` (three or four, each a `**Player v Player (time UK)**` line followed by rankings, seeds, ages, form and what the winner faces next); `## ` sections for the day's angles (home players, young players to watch, a national squad, a rivalry); `## Order of play` (every match as a list, UK times, with a line saying times are approximate); `## How to watch` (WTT's YouTube stream, Eleven's event page and live scores, the format); and a short round-up of the previous day linking to its review. Give the women's and men's draws equal weight throughout.
- **Review** (700 to 1,000 words): post it in the first run after the day's last session ends. Story `id` `<hub id>-day<N>-review`; slug `<hub id>-day-<N in words>-review-results-highlights`; `"kind": "Review"`, `"day": N`. Intro: the day's main story, covering both draws. Look for the storylines in STYLE.md (returns from injury, withdrawals, firsts, revenge, ranking consequences) before choosing it, and follow a storyline from the previous day's coverage through to its end. Then `## ` sections on the main matches, upsets, comebacks and records (shortest and longest matches, saved match points), with quotes from published interviews; `## Results in full` (every match as a list, "Winner (NAT) bt Loser (NAT) 11-8, 11-6, 11-8"); and a closing section on the next day's headline matches linking to the next preview. `matches`: the day's four key results, two women's and two men's. If separate stories were published during the day, merge them into the review rather than leaving short pages: remove them from `news.json`, delete their article files and add a `301` line for each old URL to `_redirects`.
- **Highlights**: add up to four of the day's official WTT highlights to the review's `videos`, two women's and two men's, the most important match first. Get them from Eleven's own highlights feed through the probe workflow: run it with `https://tt-news.tommorti.workers.dev/api/highlights?q=<stream_q from the hub in data/events.json>` and read `videos` (each has `id`, `title` and `gender`). Use only clips of matches played that day. WTT often posts them late at night or the next morning, so on each run check the latest review: if it has fewer than four clips and more are available, add them.
- Keep the day count from the tournament's first day of play (day one = `start` in `data/events.json`). If a review for the day already exists, update it rather than adding a second.

## When a tournament finishes

The site switches itself over once every final in the event's draw (`data/draws/<id>.json`) has a winner, so keep the draw synced through finals day. Then:

- The homepage drops the "On now" panel, the news leads again and the scores strip returns.
- A Champions panel (both singles winners, final scores, links to the finals report, results and the next event) sits under Top stories for three days after the end date, or until the next big event starts.
- The event page shows "Finished", a Champions section at the top, and no live scores or calendar button.
- Previews for the event drop out of Top stories; the finals review (the last day's `Review`) gets a boost to lead.

Your job on finals day: publish the finals review as the `top` story, written as the celebration of the winners (headline names both champions). Mark the next tournament's preview as the second story. Don't write "the tournament continues" or "day N" language in anything published after the last final.

- Internal links: the build links the first mention in each story of every event page (full name, name and year, or host city) and of the world rankings automatically. Still add by hand the links the build can't know about: earlier stories, previews and reviews, guides (`[words](/news/<slug>.html)`), and the right anchor (`/events/<id>.html#matches`, `#watch`) where it helps the reader.
- Times: pages are built in UK time and /localtime.js converts `<time data-lt="hm|dhm" datetime="...Z">` to the reader's time zone; JS-drawn times (live.js, fixtures.js) already use the browser's zone. Any new scheduled time on an event page must use that markup and sit near a note saying times are approximate.
- Tables: where an event uses one table, cards, fixtures and the match centre name the venue (set `venue` on the event in data/events.json) instead of "Table 1".

## Club leagues

The Clubs section (`/clubs/` and a page per league, built by `tools/build_clubs.py`) reads `data/clubs/<competition>.json`.

- Automatic (`"auto": true`): `ttbl`, `dttbl-women`, `tleague-men`, `tleague-women`, `mltt`. `.github/workflows/club-sync.yml` refreshes them every hour from the leagues' own sites (`tools/club_sync.py`). Don't edit these by hand. If one stops updating (its `updated` time is more than a day old during the season), check the workflow log and fix the parser. Each new season: add the women's Bundesliga group id to `DTTBL_GROUP` in `tools/club_sync.py` (shown on the DTTB click-TT league page) and check new club names in `TTBL_NAMES`, `DTTBL_NAMES` and `TL_TEAMS`.
- By hand (`"auto": false`): `proa-men`, `proa-women` (FFTT and the clubs' sites), `cttsl-men`, `cttsl-women` (CTTA, Xinhua, Sina, Tencent), `cl-men`, `cl-women` (ETTU), `utt` (Ultimate Table Tennis). In every run where a league in season has played, update its file from the official source or two reliable reports: `status`, `updated`, the table and new results (`score: [home, away]`, `status: "finished"`), and the next fixtures. Use `"when": null` with a `round` when the date isn't known, and `"date_only": true` when only the day is. Never guess a score, date or table position. Same format as the automatic files (see the docstring in `tools/club_sync.py`).
- News: club stories appear on their league page when the headline or summary names the league. Add `"league": "<slug>"` (`bundesliga`, `super-league`, `t-league`, `pro-a`, `champions-league`, `mltt`, `utt`) to any club story that doesn't, and write club news as before (category Clubs, equal weight to men's and women's leagues).


## Club squads

- Squads for every league on the Clubs pages live in `data/clubs/squads/<competition>.json` and show in a Squads section on each league page, with players linked to their profiles.
- Automatic (`"auto": true`): `ttbl`, `dttbl-women`, `tleague-men`, `tleague-women`, `mltt`, `utt`. `tools/squad_sync.py` refreshes them once a day in the club-sync workflow. Don't edit these by hand; if a parser breaks (a team with no players), fix it.
- By hand (`"auto": false`): `cttsl-men`, `cttsl-women` (each club's registered squad, from CTTA or reliable Chinese reports, names in pinyin, family name first), `cl-men`, `cl-women` (ETTU's team roster PDFs on the competition pages), `proa-men`, `proa-women` (not yet filled: build them from the clubs' own sites and FFTT match reports, never from Wikipedia alone).
- Monitoring: on every run, check the news scan and the leagues' own news for transfers, signings, loans, retirements and injuries that change a squad, and update the manual files the same run (set `updated`). A transfer of a ranked or profiled player is also a news story. Each new season, replace the squads once the leagues publish them.

## Past events and full draws

- The WTT sync saves every draw WTT has for an event on now (singles, doubles, mixed and team), and the event page shows them as tabs in the draw and as filters in Matches. By hand: `python3 tools/fetch_draw.py <wtt id> "<name>" <utc offset> --all`.
- When an event finishes, its page shows the Champions from the draw. For events not on WTT (continental championships, the Asian Games), add `champions` to the hub in `data/events.json`: `[{"event": "Men's singles", "champion": {"name", "nat"}, "runner_up": {"name", "nat"}, "score": "4-1", "games": "11-5, ..."}]`, leaving out what isn't known.
- Every finished event Eleven did not cover day by day gets a `story` on its hub: three or four paragraphs, "How it was won", in STYLE.md style, covering both draws, the finals, upsets of top seeds and the storylines. Facts come from the draw file or checked sources.

## Event pages for past years

A nightly scheduled task builds the event pages for one past year at a time (2025, then 2024, 2023, 2022, 2021), following "Past events and full draws" above: the qualifying events of that year (WTT Champions, Star Contender, Grand Smash, WTT Finals, World Cup, World Championships, Olympics, continental championships, Asian Games and European Games), with draws from WTT where the event is in its system and champions otherwise. Older pages carry a shorter "How it was won": two short paragraphs (finals and the main storyline), not four. New hubs are appended to the end of `events` in data/events.json so existing posters keep their look.

## Tags

Every story gets up to three tags (tournament, players, club or league, country) automatically at build time, old and new alike. The tags show under the headline on cards and articles and link to /tag/<name>, a page with every story on that tag, a short header and links onward. Rankings link every player and country that has stories to its tag page.

- Nothing to do for normal stories. The build reads the headline, standfirst, body, match cards and event.
- To force a tag on a story, add `"tags": ["Name", ...]` to the article (or story in news.json). Use the exact name of a player or competition.
- To add a competition with no event page, a player outside the world top 100, a club or a country the build does not know, add an entry to `data/tag-registry.json`: `{"type": "tournament|player|club|country", "name": "...", "aliases": ["..."], "nat": "XXX"}`. Players in match cards are picked up automatically.
- Tournaments with an event hub use the hub (so `WTT Champions Frankfurt 2026` links to the event page). Other competitions are listed in `COMPETITIONS` in `tools/tags.py`.
- A tag page with one story is kept out of Google (noindex) until it has two.
- Rules of thumb: a tournament tag needs the name in the headline or standfirst; a player needs the name in the headline or standfirst, or three mentions in the body; countries and clubs are the lowest priority.

## Player profiles

**Who gets a page** is decided by `tools/people.py` on every build, never by hand. Under 16: never. 16 or 17: only if they already play senior events (senior world top 100 now or before, or a main-draw match at WTT Contender level or higher). No date of birth: only with that senior record, and not at all if they have any youth-event record (they wait until `data/players/wanted.json` gets their date of birth from WTT via the match sync). Adults: the senior record, a club squad place, or a written bio. Youth events never count. Anyone else is plain text: no link, no tag chip, no page. Players with a page but no bio file get a page built from results and news; writing a bio file for them upgrades it. Player tags link to the profile's News tab, and old `/tag/<player>` links redirect there (`_redirects`, generated section).

The top 10 men and women have profiles at /players/<slug> (`data/players/<slug>.json`, one file per player; `wtt.json` beside them is written by the match sync, never by hand). Results, recent matches, season records, tour titles, head to heads and the ranking history come from Eleven's match database (`data/matches`, filled every six hours by `.github/workflows/match-sync.yml` from WTT's official results), so they update themselves. The bio file holds what the database can't know:

- `born`, `birthplace`, `height_cm`, `hand`, `grip`, `style`, `coach`
- `clubs`: `[{"club", "league"?, "from"?, "to"?, "current"?: true}]`, oldest first; mark every club the player plays for now with `"current": true` (players often have a club in more than one league, e.g. the T.League and the China Super League)
- `equipment`: `{"blade", "forehand", "backhand", "sponsor", "confirmed": "YYYY-MM-DD", "source": url}`
- `honours`: medals at the Olympics, World Championships, World Cup, WTT Finals and continental championships and multi-sport games, `{"year", "event": "<Competition>, <discipline>", "result": "Gold|Silver|Bronze"}`
- `notes`: a sentence or two of current context shown at the top of the profile (an injury, a comeback, a change of association), each one dated in its words
- `sources` (every page a fact came from) and `checked` (date)

Every player in the world top 100 has a profile. Players outside the top 10 started as stubs (`"stub": true`): name, association, date of birth and playing hand from WTT, with results from the match database. The monthly check fills in up to 30 stubs a month, highest-ranked first (birthplace, height, grip, style, clubs, equipment, honours, sources), then removes `"stub"`. Don't take grip or style from WTT's player data: it is unreliable (it lists Dang Qiu as penhold).

A profile is permanent: once a player has a file, never delete it, even if they drop out of the top 10 or the top 100, retire or change association. Their results, records and news keep updating from the match database and the tags, the monthly check keeps their bio file current, and the page shows "Outside the world top 100" when they have no ranking.

To add a player (when someone enters the top 10, or later the top 20 and beyond): create the file with `name` exactly as in data/rankings.json, `ittf_id`, `nat`, `gender` (M or W), then research the rest from Wikipedia, the player's federation, club and sponsor pages, citing each. Profile pages, links from the rankings, tag pages and articles appear on the next build.

## Knock-on changes (do these in every run)

A story is never only a story. Before committing, apply what it changes everywhere else on the site, in the same commit:

- **Player profiles**: an injury, withdrawal or comeback → update that player's `notes` (dated, e.g. "Withdrew from WTT Champions Frankfurt in November 2026 with a back injury"), and remove notes that no longer apply; a club move → `clubs`; a new sponsor or blade → `equipment` with `confirmed` and `source`; a medal at a major championship → `honours`. Match results need nothing: the match sync adds them.
- **Event pages**: withdrawals, venue or date changes and champions go into `data/events.json` and the schedule; a finished event Eleven did not cover day by day gets its `story`.
- **Club pages**: league results and table changes for the manual leagues (see Club leagues).
- **Tags**: a player or competition the build does not know goes into `data/tag-registry.json`.
- **Rankings**: if WTT publishes a new ranking, the sync picks it up; mention big moves in the news.
- **Earlier stories**: correct anything a new story shows to be wrong, adding `modified`.

## Results beyond WTT

- WTT and ITTF events (feeders included) come from WTT's results via `tools/match_sync.py`. Club leagues come straight from the leagues' own sites via `tools/league_sync.py` (`.github/workflows/league-sync.yml`, every six hours) into `data/leagues/<league>/<season>.json`: so far the Tischtennis Bundesliga (ttbl.de) and the Nojima T.League (tleague.jp). Use these files as the primary source for club results and quote the league's own match page.
- 11EDGE (11edge.io) is a reference only. Its terms forbid scraping and its robots.txt blocks AI crawlers, so never fetch it in a run. If Tom pastes one of its pages, it can be used to cross-check a fact and credited as "11EDGE".
- Never publish betting odds, implied probabilities, tips or anything about gambling, and never use odds sites as sources.
