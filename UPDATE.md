# How each update run works

The site is static. All content lives in `data/news.json`; `index.html`, `styles.css` and `app.js` only change when the design changes. Each scheduled run follows these steps.

1. Pull the latest `main`.
2. Search for table tennis news published since `updated` in `data/news.json`, in English and in the original languages. Search in each language with native terms (for example 乒乓球, 国乒, 乒超 in Chinese; 卓球, Tリーグ in Japanese; 탁구 in Korean; Tischtennis in German; tennis de table in French). Check, as a minimum:
   - International: worldtabletennis.com, ittf.com, ettu.org, butterflyonline.com
   - China: Xinhua and China Daily sports, CCTV Sports, NetEase (163.com) and Sina sports, the Chinese Table Tennis Association, China Super League coverage
   - Japan: jtta.or.jp, tleague.jp, TV Tokyo table tennis, Spread Sports
   - Korea: KTTA, Star News Korea, Yonhap
   - Germany: tischtennis.de, ttbl.de, mytischtennis.de
   - France: fftt.com
   - India: Ultimate Table Tennis, TTFI
   - England and UK: tabletennisengland.co.uk, Table Tennis Scotland and Wales
   - news for any event in `events` that is on now

   Write all stories in English. For a story based mainly on a non-English source, add `"lang"` with the language name (for example `"lang": "Chinese"`) and add the language in brackets to the source name, such as `"NetEase (Chinese)"`. Translate names using standard English spellings (Wang Chuqin, not 王楚钦). When English and non-English sources disagree, prefer the most recent report from the source closest to the player or federation, and say who reported it.
3. Add new stories. For each one:
   - `category` is one of International, England, Clubs, Equipment.
   - Write the headline and a summary of one to three sentences in your own words. No copied sentences, and any quote under 15 words.
   - Link every source used. Leave out anything sources contradict rather than guessing.
   - For a story about a single match result, add `"score"` (for example `"3-2"`), which appears on the story's artwork.
   - Give the story an `image` where a suitable one exists, in this order of preference:
     0. If the story has official video (`videos`), the first video becomes the lead image automatically, so no `image` is needed.
     1. A photo of the main player from Wikimedia Commons, only where the file page names that player and the licence is CC0, public domain, CC BY or CC BY-SA. Use crowd or group shots only if the player is clearly the subject. Format: `{"type":"photo","url":"<1280px upload.wikimedia.org thumbnail>","alt":"...","caption":"<who, where, year>","credit":"<author as on the file page>","licence":"CC BY 4.0","licence_url":"...","page":"<Commons file page>"}`.
        Never use a photo that shows another event's branding (for example Olympic, Pan American Games or World Championships livery on a story about a different tournament). Only use an event-branded photo when it is from the same event as the story. When in doubt, use an illustration instead.
     2. A generic table tennis photo from Unsplash or Pexels for stories without a single named player (equipment, clubs, rule changes), in the same format with the photographer as credit and "Unsplash Licence" or "Pexels Licence".
     3. An illustration for stories tied to a place or an object: reuse one in `img/cartoons/` if it fits, or add a new one to `tools/draw_illustrations.py` and run it. Match the existing style exactly: black fine-line drawing with hatching, `currentColor` strokes, no colour, no text except plain labels, no jokes or speech bubbles, and never a real person's likeness. Format: `{"type":"cartoon","src":"img/cartoons/<name>.svg"}`.
     4. Otherwise leave `image` out and the site draws its own table illustration.
     Never use photos from news sites, WTT, ITTF or federations, and never use a photo whose licence you could not check.
   - Results: whenever a story or article reports match results, add `"matches"` (format documented at the top of `tools/components.py`). The first entry is the headline result and appears as the scoreboard at the top of the page; add the other results from the same story after it (semi-finals, other finals, team ties). Include `"games"` point scores only when a source gives them, checked against at least one source, in the same side order as `"sides"`. For team ties, add each rubber under `"rubbers"`. Never guess a score.
   - Headlines name the competition in full: "WTT Champions Montpellier", "WTT Star Contender Muscat", "Singapore Smash", "WTT Finals Hong Kong", "Asian Championships", "China Super League", never just the host city or venue ("Montpellier draw" is wrong; "WTT Champions Montpellier draw" is right). The same applies to `title`, `headline`, `standfirst` and scoreboard `event` labels.
   - Equal prominence: never give one gender's results more prominence than the other's. If a story covers both men's and women's events, its `matches` must include at least one men's and one women's result (labels starting "Men's" and "Women's"); the site shows them side by side at the same size. Don't put a single-gender score badge (`score`) on a story that covers both. The same goes for headlines, standfirsts and lead paragraphs: where a story covers both, lead with both, not just the men's result.
   - Draws: when an event's draw is published, create `data/draws/<WTT event id>.json` and set `"draw": "<id>"` on the draw story and article. Try `python3 tools/fetch_draw.py <id> "<event name>" <host city UTC offset>` first. If WTT can't be reached, keep the file current by hand from published results: after each round, fill in `winner` (0 or 1), `score` (e.g. "3-1") and the next round's players, and set `updated`. Use the same names as the rest of the site.
   - Videos: add `"videos"` (YouTube `id`, a short `title` in the form "Player A vs Player B, round", and `channel`) when official highlights or full matches exist. Only use channels run by WTT, the ITTF, continental or national federations, league organisers, or their broadcast partners (TT11TV describes itself as a WTT and ETTU partner). Before adding a video, check its title and uploader with `https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<id>&format=json`; skip it if you can't confirm it's the right match and an approved channel. Highlights often appear a day or two later, so on every run, check stories and articles from the last seven days that have results but no videos.
   - Social posts: add `"social"` (`platform` "instagram" or "x", the post `url`, and `account`) for posts from official accounts only: WTT (@wtt), the ITTF (@ittfworld), continental and national federations, leagues, clubs and the players' own verified accounts. Pick posts about the story's event with match photos or video, check the caption matches, and keep it to one or two per story. Where a story covers men's and women's events, don't feature only one side.
   - Adding or correcting `matches`, `draw`, `videos`, `social` or `image` on an already-published article is a data update, not new writing: commit it straight to `main`, set the article's `modified` time, and leave the article text alone. Changes to the article's wording still go through a review pull request.
   - Lead story (`"top": true`, exactly one story): choose it on every run with these rules, in order.
     1. While an event with prestige 3 or more in `data/schedule.json` is on, the lead comes from that event: the draw before play starts, then the day's main results, then the finals.
     2. Otherwise, the newest significant story leads, ranked first by the event's prestige tier, then by how recent it is.
     3. No story stays as the lead for more than about 24 hours if anything comparable has happened since.
     4. When the best men's and women's stories are of similar weight, alternate between them so neither side holds the lead slot run after run. Check which side the previous lead covered.
   - Event hubs: major tournaments have a hub page built from `data/events.json` (`/events/<id>.html`) with Eleven's poster, results, draw, schedule, videos and news. Set `"event": "<hub id>"` on every story and article about a hub event; its results, videos and links then appear on the hub automatically, and the poster becomes the lead image unless there is official video or a suitable photo. Add a hub for each WTT Champions, WTT Star Contender, WTT Finals, Grand Smash, World Cup, World Championships, Olympic and continental championship event at least two weeks before it starts (`id`, `schedule_id` matching `data/schedule.json`, `name` as used in headlines, `group` "WTT Series", "Majors" or "Continental", `tier` from the poster tiers in `tools/posters.py`, `series`, `city`, `country`, `year`, `start`, `end`, optional `venue` only if confirmed, `events`, `coords`, `draw` once published, `live: true` for WTT events). Then run `python3 tools/posters.py <hub id>` to render `img/posters/<hub id>.jpg` and commit it. Illustrations stay for stories not tied to an event (equipment, features, rule changes).
   Every short story also gets its own page on the site, built automatically from `data/news.json`. Give every new story a `published` time (current UTC time, ISO format, to the minute, spaced a few minutes apart when adding several). Optionally give a story a `body` (a list of one to three short paragraphs, up to about 150 words) when there is more verified detail than fits the summary; otherwise the page shows the summary. Short stories publish without review.

   Full articles (review first):
   - When a story has enough verified material for roughly 250 to 350 words without padding (usually two or more sources, or one detailed primary source), also write a full article as `data/articles/<slug>.json` with: `slug` (kebab-case, unique), `story_id` (the matching story's `id` in `data/news.json`), `category`, `date`, `published` (the current UTC time in ISO format, to the minute; if you add several articles in one run, space their times a few minutes apart), `title` (under 90 characters), `standfirst` (one or two sentences), optional `lang` and `image` (same rules as stories), `body` (a list of paragraphs), and `sources`. Don't pad thin stories: short items stay short.
   - Byline: set `"author"` on every new story and article by section: International is Michael Dobbs (`michael`), England and Clubs are Michelle Nemeth (`michelle`), Equipment is Tom Mortimer (`tom`). A story with a full article uses the same author as its article.
   - Style: British English, plain and factual, past tense for results, specific numbers and scores, attribution for anything reported rather than confirmed ("according to NetEase"). Keep allegations, reported claims and confirmed fact clearly separate. Quote only words that appear exactly in a source, under 15 words. No AI disclosure line, no clichés, no em dashes, no padding about "the broader landscape".
   - Check every name, score, date and ranking against the sources before writing. If sources conflict, say so in the article or leave the detail out.
   - Never commit full articles to `main`. Put them on a review branch: if an open pull request titled "For review: ..." already exists (`gh api "repos/morti31/tt-news/pulls?state=open" --jq '.[] | [.number, .title, .head.ref] | @tsv'`), add the new files to its branch; otherwise create a branch `review/YYYY-MM-DD-HHMM` from `main`, commit the article files, push it and open a pull request with `gh api repos/morti31/tt-news/pulls -X POST -f title="For review: <number> articles" -f head="<branch>" -f base=main -F body=@body.md`, where body.md comes from `python3 tools/review_body.py <every article file on the branch>` so Tom can read each article in full and merge from his phone. Then run that same command again after adding articles to an existing branch, and apply it with `gh api repos/morti31/tt-news/pulls/<number> -X PATCH -F body=@body.md` (use the REST API: GraphQL-based `gh pr` commands are blocked). Keep the title count current with the same PATCH call. Tom publishes by merging it. The short version of the story still goes on `main` as normal, and the homepage links it to the full article once merged.
   - Don't commit anything in `news/`, `sitemap.xml`, `robots.txt`, `feed.xml` or `data/article-index.json`: Cloudflare builds those from the article files with `python3 tools/build_site.py` on every deploy.
4. Remove stories older than 14 days. Keep at most 30.
5. Update `results` with finished matches from events on now or just ended (finals and semi-finals for WTT events, title-deciders for club competitions). Keep the three most recent events.
6. Update `rankings` only from the official ITTF world ranking, published by WTT at https://www.worldtabletennis.com/rankings (its data file is https://wtt-web-frontdoor-withoutcache-cqakg0andqf5hchn.a01.azurefd.net/ranking/SEN_SINGLES.json: use `SubEventCode` "MS" and "WS", `CurrentRank`, `RankingPointsYTD` and `PreviousRank`). Never take rankings or points from Butterfly, Tabletennis Reference or other third parties. When a new ranking week is out, rewrite the men's and women's top 10 as `{"name", "nat", "points", "prev"}`, with names in the form "Sora Matsushima" / "Wang Chuqin", and set `week` to "ITTF world ranking, week N, D Month YYYY". If the official list can't be reached, leave the rankings as they are.
7. Keep the schedule in `data/schedule.json` current (`data/news.json` no longer holds events):
   - Add newly confirmed tournaments and club competitions from the ITTF/WTT, ETTU, TTBL, T.League, CTTSL and UTT calendars, and move anything in `tbc` into `events` once dates are published. Leave past events in place; the site hides them.
   - Add `fixtures` with real times (UTC, ISO format, with `event_id`, `name`, `start`, `end`, `source`) for any event within the next 14 days: session times as soon as the organiser publishes them, then notable matches once the draw is out, for example `"WTT Champions Frankfurt: Lebrun v Moregard, quarter-final"`. Use times from the organiser, live-score sites (WTT, Flashscore, SofaScore) or the federation, and convert local times to UTC. Keep each fixture's `id` stable when updating its time, so subscribers' calendars update rather than duplicate.
   - Remove fixtures more than 7 days old.
   - Run `python3 tools/build_site.py`, which checks the schedule (fix anything it prints as a "schedule warning") and rebuilds `calendar.ics`. Commit `data/schedule.json` and `calendar.ics`. Cloudflare also rebuilds the calendar on every deploy, so it always matches the schedule.
   - Check every live or upcoming event in the next 14 days on each run, not just new ones: if a date, venue, session time or match time has moved, update the existing entry in place (same `id`) rather than adding a new one.
8. Set `updated` in both JSON files to the current UTC time, check the JSON parses, then commit with a message like `Update 2026-10-27 09:00` and push.

## Schedule

Every 4 hours as standard. Hourly while an event with prestige 3.5 or above is on (Mixed Team World Cup, WTT Finals, China Super League Finals, Grand Smashes, World Championships, Olympics).
